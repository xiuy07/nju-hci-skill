# 交互原则与评审

课程依据：pp. 2–8、23–25。原则名称经一手来源核对。

## EEC 与两个隔阂

七阶段：形成目标、形成意图、明确动作、执行动作、感知状态、解释状态、评估结果。

执行隔阂关注目标如何变为可理解、可执行的动作，检查入口、命名、映射和步骤；评估隔阂关注能否从状态判断发生了什么、是否达成目标，检查进行中、成功、失败与下一步。

扩展框架描述 U 任务→I 输入的表达、I→S 系统的执行、S→O 输出的表现、O→U 的观察。按需要定位转换阻碍，无需每次画全模型。

课程可用性目标为易学、易记、效用、效率、安全。加入任务成功与满意度等指标时说明是分析扩展。可用性也含主观感知，UX 也可系统研究，不作“可用性全客观、UX 全主观”的严格二分。

## Nielsen 十项启发式

| 原则 | 关注点 |
| --- | --- |
| 系统状态可见 | 进行中、完成和失败能否被感知 |
| 符合现实世界 | 术语、顺序、映射是否符合用户理解 |
| 用户控制与自由 | 取消、返回、退出与适当撤销 |
| 一致性与标准 | 语义一致并遵循平台惯例 |
| 防止错误 | 提前发现与纠正易错条件 |
| 识别优于回忆 | 所需信息可见或易取回 |
| 灵活性与效率 | 新手和熟练用户的合理路径 |
| 审美与简约 | 内容服务目标，重点清楚 |
| 错误识别、诊断、恢复 | 解释问题，提供可执行办法 |
| 帮助与文档 | 在需要时获得任务相关说明 |

将原则对应到具体用户任务，不要求凑齐十项或给每项相同权重。[Nielsen 原始说明](https://www.nngroup.com/articles/ten-usability-heuristics/)

## Shneiderman 八条黄金规则

保持一致；支持普遍可用性；提供有信息量的反馈；让操作序列有明确结束；防错；易于撤销；让用户保持控制；降低短时记忆负担。

“结束”指闭环反馈和完成感，不是所有动作弹对话框。与十项启发式有交集，不强制逐条对应。[作者提供的规则](https://www.cs.umd.edu/users/ben/goldenrules.html)

## 选择方法

启发式评估按原则检查界面，可先整体再局部。多位评估者可独立记录后合并；课程的 3–5 位是常见安排。单个 AI 扮演多个角色不能计为多位独立专家。

认知走查以新用户和具体任务为起点，逐步问：是否形成正确的下一步目标，能否注意并理解正确动作，动作后能否判断进展。课程压缩为可预见、可理解、可解释。记录每步假设和失败原因，不用专家知识代替新手判断。

协作走查可包含用户、开发人员和专家；经典专家认知走查通常不依赖真实用户。按实际参与安排说明，不按名称硬判有无用户。

## 输出发现

记录位置或步骤、证据、目标影响、原则、严重程度及理由、建议、验证方式。截图只支持可见事实，未观察的状态标待验证。

课程严重程度：0 非问题；1 表面问题；2 轻微；3 重要；4 可用性灾难。结合影响、频率、恢复难度判断；频率未知时不捏造。这套 0–4 分不等同于软件 P0/P1。

自拟例：提交后无可感知状态可能导致重复点击，对应评估隔阂与状态可见。静态图只能提出待验证风险；实际观察后才写行为事实。建议明确提交中和结果、保留失败输入，在测试中观察能否判断结果及是否重复提交。
