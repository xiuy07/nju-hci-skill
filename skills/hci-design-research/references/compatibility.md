# 版本与平台适配

## 区分四种版本

skill 版本、项目/平台版本、标准/模式版本、研究与数据版本分别记录，不能用 skill 已升级来证明项目兼容。只检查与当前决定有关的维度。

本技能为 2.0.0，中文与英文保持相同调用名和功能边界，选择一个语言包安装。Markdown 指令是核心，客户端的 UI 元数据能力可能不同；不声明未经验证的最低客户端、模型或操作系统版本。

## 实际项目的适配流程

1. 从项目配置、锁文件、运行环境或用户约束识别实际版本。代码和运行结果优先于推测，未获取到的版本标未知。
2. 定位涉及版本差异的行为：例如模态框焦点、路由返回、表单校验、状态通告、统计 API 参数。没有行为差异依据时不强行升级。
3. 查对应版本的官方文档，区分标准要求、推荐模式与组件库实现；在线最新文档不能证明旧版本支持。
4. 给最小可行方案：现有组件能力、局部兼容层、降级路径或需要用户决定的升级。保持项目原有技术栈，不静默修改依赖大版本。
5. 在实际目标环境验证主任务与相关辅助输入。记录测试过、仅查文档、未验证或不适用，不把“设计上可用”写成已支持。

需要时用小表：

| 环境/版本 | 相关行为 | 方案 | 证据/验证状态 |
| --- | --- | --- | --- |
| 项目锁定的组件库版本 | 关闭对话框后焦点恢复 | 优先用现有回调；按需补恢复 | 运行后记录实际结果 |
| 目标浏览器与屏幕阅读器组合 | 状态消息是否感知 | 合适语义并核验 | 未测试则明确待测 |
| 已安装统计库 | 方法参数与结果字段 | 使用该版本支持接口 | 运行最小相关计算核对 |

## 平台与规范

Web 的 CSS px 不等于原生平台的点或密度单位。移动端检查软键盘、触摸与生命周期，桌面检查键盘和多窗口；混合应用按实际嵌入层行为判断。相同视觉组件可能有不同输入约定。

WCAG 2.2 可作为明确选择的 Web 基线，不代表所有项目都被要求采用某一级别。符合性是完整范围的声明；模式指南和自动扫描不能代替标准。旧基线迁移时记录新增、变化和仍待测试项；不将某个候选新标准自动当已正式要求。

中英文切换除文字外，还应核验布局膨胀、日期数字、时区、排序、输入法和术语。对外研究报告可用用户要求的语言，不受安装包语言强制约束。

## 研究与分析的版本

记录产品构建、原型、任务文本、量表语言/版本、埋点定义、随机化逻辑、数据模式和分析库。条件间若同时更换构建，不能把所有差异归因于目标设计。

合并新旧数据前映射单位、事件和类别，保存转换规则。量表翻译不自动具有测量等价性；无可比依据时分开报告。分析需能说明清洗、随机种子和软件版本，旧软件缺接口时使用适当等价方法或报告限制。

## v1 升级与回退

调用名保持 `$hci-design-research`。升级前备份已安装目录，检查本地定制；替换整个包，避免遗留来源文件或不同语言文件混用。v2 将实验分析拆成独立参考文件，新增版本适配与 AI 交互，出处集中至仓库 README。

切换中文/英文使用同一安装目录中的完整语言包，不能同时安装两个同名发现入口。回退时恢复完整备份或明确旧提交；不要声称目录中的版本字符串等于客户端已重新加载，需以随后实际读取结果为准。
