# 人机 AI 协作界面

仅在系统包含推荐、预测、生成或自动化能力时读此文件；普通确定性交互无需套用。

## 预期与控制

说明系统能做什么、何时可能出错。用户应能适时调用、忽略、纠正结果，并理解重要行为的依据。系统更新或偏好变化不应让既有工作流突然不可理解。

把不确定输出设计为可检查的对象，而非默认确定结论。根据实际功能提供编辑、重试、比较、撤销或转人工路径；不因带“AI”就强制增加无用的解释面板。

## 将原则转成状态与任务

以下是本包用于项目设计的综合建议，不是固定界面模板：

| 情况 | 设计和验证 |
| --- | --- |
| 生成尚未结束 | 区分进行中、部分结果、完成和失败，停止后说明哪些结果保留 |
| 建议需要应用 | 区分预览、选择与真正提交，避免误以为已执行 |
| 结果不正确 | 编辑与重新生成不必要求用户重建全部上下文 |
| 自动化涉及外部影响 | 显示实际动作、范围和结果，按任务授权与风险设置控制 |
| 模型或配置升级 | 对比相同任务条件下的质量、延迟与用户表现，记录配置 |

不要用未经校准的百分比制造可靠性印象，也不要把语言流畅度当正确性。展示支持材料时检查它是否支持具体结论，不能仅显示一个看起来可信的链接。

## 评估端到端效用

先定任务和失败代价，再衡量最终正确完成、发现错误、纠正成本、时间与适当信任。接受率不等于质量，用户频繁接受可能掩盖未发现错误。比较条件应记录模型/系统版本、提示或配置、输入数据和重复策略。

不确定系统同一输入可能产生不同结果。按研究目的安排重复与采样，保存足以复现的条件，不把一次成功演示外推为稳定能力。用户研究中明确哪些是实际输出、哪些为固定或人工模拟刺激。
